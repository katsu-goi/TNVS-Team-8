# System-wide Data Table Inventory

Pre-edit baseline for the TNVS Facilities & Administrative Management System. The active React route tree (`frontend/src/App.tsx`) and canonical role navigation (`frontend/src/config/roleRegistry.ts` plus `workspaceConfig.ts`) are the source of truth.

## Scope summary

- Authenticated route entries inspected: **106** (including governance workspace sections and the protected Team 8 reservation portal).
- Raw desktop `<table>` instances: **29**.
- Additional record surfaces: generic governance workspace records, dashboards, approval cards, notification feeds, reservation timelines, and management lists.
- Existing server-side pagination: security logs and global audit routes support page/size metadata. Most other APIs return a server-authorized bounded collection and optional status/date filters, but do not expose a page contract.
- Authorization baseline: Edge handlers scope rows before the response. This modernization must not replace that with browser-only authorization or cross-scope fetching.

## Baseline issues to resolve

1. Repeated raw table markup and module-local badge/empty/error components create inconsistent headers, spacing, focus, and mobile behavior.
2. Most raw tables only wrap in `overflow-x-auto`; they do not provide a deliberate mobile record-card fallback.
3. Audit/security/AI logs show long details without one shared truncation and accessible expansion convention.
4. Many bounded module collections have no UI pagination. Because their APIs do not accept page metadata, modernization may only paginate the already authorized bounded response unless the backend contract is explicitly extended.
5. Search is missing on many decision-heavy tables. Debounced client search is safe only over the already authorized bounded result; global/large search must stay server-side.
6. Loading, no-data, filtered-empty, and retry behavior varies widely.
7. Action buttons are often repeated inline instead of using a consistent action area/menu, especially on narrow screens.
8. Status colors and terminology are duplicated in many modules.
9. Dates are generally localized but not consistently labeled as Asia/Manila, and some technical timestamp formatting remains.
10. Configuration cards, facility cards, calendars, charts, notification feeds, and the reservation timeline should retain the interaction model that suits them; standardization should apply shared primitives without forcing everything into a desktop table.

### Pagination and filtering boundary

- Global security audit logs use their existing server-side page and size metadata.
- Existing server status/date filters remain server-driven wherever the endpoint already supports them.
- Bounded collections without a page contract use client search, sort, and pagination only after the server has authorized and returned the collection.
- No new organization-wide fetch, browser-only authorization rule, or unsupported query parameter was introduced.

### Intentionally retained record experiences

Facility cards and floor plans, calendars, charts, notification feeds, approval cards that need full decision context, dashboards, integrations, system-health cards, and the Team 8 reservation timeline remain purpose-built. They are not legacy table exceptions and keep the interaction model best suited to their data.
